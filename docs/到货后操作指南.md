# 到货后操作指南

适用购买款：**ESP32-C3 SuperMini（黑色、4MB Flash、Type-C、未焊排针）**，依据用户商品图，不等于实物已验证。本项目仅 USB 常供电 + Wi-Fi，无需焊排针、接继电器或主板开机针脚。

## 1. 选板与 USB

1. 核对芯片丝印为 ESP32-C3，商品标称 Flash 4MB；插入支持数据传输的 Type-C 线。
2. 打开 Windows 设备管理器，核对新增串口。C3 原生 USB 通常是 USB Serial/JTAG；如果实物含额外 USB 转串口芯片，再按其实际型号安装官方驱动，不要预装无关驱动。
3. 项目默认 `esp32c3_supermini`，映射为 `esp32-c3-devkitm-1` 芯片配置，DIO、4MB、USB CDC on boot。SuperMini 并非该官方开发板原件，该兼容配置须到货后确认。`esp32dev` 是经典 ESP32 Xtensa 基线，不能给 C3 烧录。
4. 本固件不操作板载 LED/GPIO8，避免不同板型极性和启动绑带差异；不会等待串口终端连接，所以脱离笔记本用充电器供电也能运行。

## 2. 配置和烧录

依《配置指南》填本地 config.h，先确认既有主题协议，再准备有线网卡 MAC。设置 2.4GHz Wi-Fi，ESP32 与台式机处于同一 LAN，路由器不能隔离无线/有线广播。

```powershell
Set-Location <your-project-path>
$pio = 'platformio'
& $pio device list
& $pio run -e esp32c3_supermini
# 把 COMx 换成实测串口；初次上传先确认 esptool 识别 ESP32-C3 / Flash。
& $pio run -e esp32c3_supermini -t upload --upload-port COMx
& $pio device monitor -p COMx -b 115200
```

上传时先关闭占用串口的监视器。无法进入下载模式时：按住 BOOT，轻按并松开 RESET，再松开 BOOT，重选串口后上传；首次刷完可能要按 RESET，原生 USB 端口也可能改变。若 esptool 报芯片不是 ESP32-C3 或 Flash 不是 4MB，先停止烧录并重新调整配置，不强行绕过检查。

## 3. 只在家用台式机上准备 WOL

这些检查在目标 ROG STRIX B850-G GAMING WIFI 台式机上执行，**不修改当前开发笔记本的 BIOS、网卡、电源或 WOL 设置**。

1. 台式机通过有线以太网接路由器，安装该主板适用的官方网卡驱动。用 `Get-NetAdapter -Physical` 或 `ipconfig /all` 确认插网线网卡的 MAC，避免选到 Wi-Fi、虚拟交换机或随机地址。
2. 参考 [ASUS 官方 WOL 教程](https://www.asus.com/support/faq/1045950/)：高级 BIOS 的 Advanced / APM Configuration 中查找 Power On By PCI-E / PME 唤醒选项并启用。菜单名称以 [该主板官方手册](https://rog.asus.com/motherboards/rog-strix/rog-strix-b850-g-gaming-wifi/helpdesk_manual/)及实机 BIOS 为准，当前未实机验证具体菜单。
3. 若需要从关机状态唤醒，核对 ErP Ready 等节能设置是否切断待机网卡电源；按实际 BIOS 手册调整，不假设所有版本菜单相同。电脑关机后电源插座/PSU 开关须保持接通，断 AC 电的 G3 状态无法由本项目开机。
4. Windows 设备管理器 → 有线网卡 → 电源管理：允许此设备唤醒计算机，优先仅允许 Magic Packet；高级属性中确认 Wake on Magic Packet / PME、以及驱动提供的 Shutdown Wake-On-Lan 选项。不同驱动可能不显示相同选项。
5. 先测睡眠唤醒，再分别测休眠、完整关机及快速启动状态。微软说明 WOL 支持与 S3/S4/S5 转换及硬件有关，不能承诺关机一定可唤醒；[Microsoft 文档](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/wake-on-lan-feature)主要讨论 Windows 10，不能直接作为用户未知 Windows 版本的实测结论。若睡眠可唤醒但关机失败，结合 ASUS 建议检查快速启动和驱动关机唤醒设置，并记录改动。

## 4. 分层验收

| 顺序 | 操作 | 记录结果 |
|---|---|---|
| 1 | 台式机开机时检查有线链路、MAC、IP/掩码，与 ESP32 同 LAN | 地址和网络拓扑，只保存在本地 |
| 2 | 先用局域网可信 WOL 工具验证台式机睡眠/关机唤醒能力 | 排除 BIOS/网卡问题后再测云端 |
| 3 | ESP32 串口观察 IP、校时、TLS、SUBACK | 只保留脱敏日志 |
| 4 | APP 在家用 Wi-Fi 上，等保护期后 off→on | 应见授权、接受、3包发送；观察电脑实际启动 |
| 5 | 手机断开 Wi-Fi，仅使用移动数据，再 off→on | 验证外网 APP 路径，不需公网IP/端口映射 |
| 6 | 冷却内重复点击、非法消息、off | 不重复发包、不关机 |
| 7 | 留下主题 on，重启 ESP32、断网再恢复 | 不应自行唤醒；重新 off/on 后才接受 |
| 8 | 路由器重启、ESP32 长时间通电运行、供电波动恢复 | 重连、恢复订阅、不重放旧指令；至少观察24～72小时 |

## 5. 常见故障

| 现象 | 排查顺序 |
|---|---|
| 没串口 | 换数据线/USB口；BOOT+RESET；设备管理器核对实际 USB 芯片；先不换整套开发环境 |
| Wi-Fi 一直重连 | 2.4GHz、SSID/密码、信号、供电；访客隔离不会阻止联网但可能阻止WOL |
| 一直等 SNTP | 外网/DNS/NTP UDP123；没有有效时间不能验证证书 |
| 云连接失败 | UID、主题MQTT/TCP类型、9503出站、防火墙、证书日期/链、同Client ID互踢 |
| APP 无设备/按钮不同 | 已有主题后缀/UI类型和账号；不自行新建或删除主题 |
| 只见 need off | 保护期过后先关再开；当前为关时可先开(忽略)、关、开，确认APP确实推送off |
| 保留消息一直被拒绝 | 核对官方APP实际发送标志；保留过滤是防误触发要求，先记录行为再适配 |
| 已发送3包但电脑没开 | 日志不证明开机；查有线MAC、子网广播、AP隔离/VLAN、台式机待机供电、BIOS/驱动 |
| 只能睡眠唤醒 | 检查驱动关机唤醒、快速启动、ErP和主板S5支持，分别记录各电源状态 |
| 一段时间后反复掉线 | 退出复用同UID的MQTT调试器；检查供电、Wi-Fi和平台侧限制 |

不需要公网 IP、DDNS、端口映射、NAS、额外 App、OTA 或 Web 管理后台。首次本地验收通过后，再将 ESP32 接稳定 USB 常电供电。
