# 无硬件集成验证

验证日期：2026-11-04，Asia/Shanghai。新增25个集成场景、4,208项检查全部通过，其中包含1,000次模拟重连和唤醒循环。原有19组/848项断言、配置安全失败检查与Windows UDP回环也再次通过。

## 这次实际运行了什么

Windows MSVC 编译生产 `src/main.cpp`、`CloudClient.cpp`、`WolWifiManager.cpp`、`WolManager.cpp`、`WolCore.cpp`，并运行固定版本 ArduinoMqttClient 0.1.8 的实际解析器。

模拟对端把原始 MQTT 字节流送入客户端，依次经过连接认证、订阅应答、消息回调、连接代号与队列有效期检查、指令保护逻辑，最后到生产 WOL 发送模块。Wi-Fi、套接字、串口、时钟、FreeRTOS任务/队列和UDP接口由测试替身提供；集成测试没有连接任何云账号或发送任何网络数据包。

为适配 MSVC，仅在被Git忽略的 `.native/cloud` 目录生成上游源码副本，将4处变长栈数组替换为vector缓冲区，1处GCC packed语法替换为MSVC pack，并静态检查CONNECT头大小。解析逻辑不变，固件继续使用未经修改的上游库。测试脚本核对原始 `MqttClient.cpp` 的SHA256，版本或文件变化时拒绝静默继续。

生产代码的调整仅为提取云连接初始化函数，以及增加仅在 `WOL_HOST_TEST` 下生效的测试入口和合成配置选择。正常固件的认证、防误触发和WOL规则保持原有行为；这一组验证未发现需要修改的固件功能缺陷。

## 通过的场景

| 范围 | 实际验证的行为 |
|---|---|
| 正常开机链路 | MQTT 3.1.1、UID用作Client ID、clean session、QoS0订阅；保护期结束后off/on触发3个102字节包 |
| 实测会话标志 | 模拟服务器返回Session Present=1且成功码0，实际MQTT库与生产业务模块仍可连接并执行受保护的新指令 |
| 连接异常 | CONNACK拒绝、SUBACK拒绝或返回QoS1、无CONNACK超时；重试间隔内不反复连接，恢复后可重新授权 |
| 传输失败 | 模拟TLS连接失败仍只尝试9503，不发送MQTT数据、不降级9501；此场景不模拟密码学验证 |
| Wi-Fi不可用 | 离线时不尝试云连接；模拟Wi-Fi恢复后能连接并处理新指令 |
| 历史与重复消息 | SUBACK前off/on、连接保护期off/on、Retain及DUP标志不能唤醒；后续新off/on可以唤醒 |
| 分片与连续消息 | 逐字节延迟送达和连续多帧均通过实际MQTT解析器，不丢失合法off/on语义 |
| 队列保护 | 队列溢出使连接失效；超过2秒的排队命令、断线前遗留的命令不能唤醒 |
| 冷却 | 15秒内重复off/on不重复发包，冷却结束后的新授权可唤醒 |
| 心跳 | 对端不返回PINGRESP时离线；重连、等待保护期及重新off/on后恢复 |
| 异常消息 | 不完整payload、错误主题、空payload、超长帧及QoS1均不能唤醒，并断开以丢弃异常帧 |
| 反复重连 | 1,000次模拟断线→重连→保护期→单独on不唤醒→新off/on；每次恰好新增3次UDP发送 |
| 日志 | 场景检查日志中未包含合成UID及Wi-Fi密码 |

原始输出：[cloud-integration.log](evidence/cloud-integration.log)。可机读结果：[cloud-summary.json](evidence/cloud-summary.json)。案例实现：`test/test_cloud.cpp`；模拟接口：`test/cloud_fakes/`。

## 如何复现

使用现有Windows Visual Studio Build Tools/MSVC、Python和PlatformIO，不安装新工具。首次需先构建C3目标以取得固定版本的MQTT依赖。本轮固件构建前确认本地配置与占位模板完全一致。

```powershell
Set-Location <your-project-path>
python tools\run_tests.py
python tools\run_cloud_tests.py
```

集成测试强制选择合成测试配置，不读取本地 `include/config.h`。每个场景在独立进程运行，防止静态状态跨场景遗留；每个进程有30秒墙钟超时。日志和JSON结果写入 `docs/evidence/`。

另用 `python tools\check_tls.py` 实际直连 `bemfa.com:9503`，仅加载固件内同一根证书，TLS1.2、P-256、主机名和证书链验证通过；不发送MQTT CONNECT或用户凭据。当前服务端叶证书到期时间仍为2026-11-10 07:04:30 UTC，到货时可再次运行此检查。正常续证且根证书不变时不需修改固件；应同时检查设备时间。

## 尚不能由这套测试证明

- 1,000次循环使用虚拟时间，没有经历真实长期联网。它不等于24～72小时稳定性测试，也不测ESP32堆内存增长。
- FreeRTOS任务由测试依次推进，没有真实并发，不能证明板端调度、竞态、栈余量或TLS内存峰值。
- Wi-Fi、DHCP、SNTP和TLS握手仍须在C3上实测；本机证书验证通过不等于板端握手通过。
- 后续已完成本机真实UID认证、主题协议、网页及MuMu内Android App消息验证，见[真实云端验证](真实云端验证.md)；板端接入仍未验证。
- 模拟UDP和本机回环不能证明家庭路由器广播可达、有线网卡接收正常或电脑成功开机。
- 普通off/on依然无法辨别被当作新消息重放的完整旧off/on对，此协议限制保留。
