## 实测发现

两次CONNECT均请求Clean Session，但服务器返回的CONNACK载荷都是 `[1, 0]`：成功码为0，同时Session Present为1。这与Clean Session期望的会话标志不一致。不能仅依靠clean session声称历史状态已清除。

固件保留SUBACK前丢弃、重连3秒保护、新off/on授权、Retain/DUP拒绝以及队列代号校验。新增 `session_present` 回归场景，使用实际ArduinoMqttClient及生产业务模块验证该应答仍能连接和处理受保护的新指令；共25个集成场景、4,208项检查通过。

本次初始订阅及重连后5秒观察未收到历史消息；这只是本次观察，不能保证平台以后不会同步历史，也不能消除完整旧off/on对的重放限制。

## 复现与边界

在本地忽略文件中提供 `uid`、`topic` 两个JSON字段后，显式运行：

```powershell
python tools\check_live_mqtt.py
```

程序只向巴法云建立TLS/MQTT连接、订阅与发心跳，不主动发布控制消息，也不发WOL。提示等待后在现有主题网页发送off、on；最多等待240秒，收到两条匹配消息和心跳后再测试重连，最后退出。同一Client ID的其他客户端应先停止，避免连接冲突。该脚本不属于默认离线测试流程。

仍需到货验证：ESP32的Wi-Fi、SNTP、TLS内存、FreeRTOS调度、固件使用真实配置接入、家庭广播到台式机以及24～72小时稳定性。正常固件无需为本轮验证修改行为或重新构建。
